## 一、决策：故障注入怎么做

### 决策 1：用**装饰器**注入，不改检索链路一行代码

`catalog_search.py` 已经有完整的降级链（`hybrid_rerank → … → keyword_2gram`），
每一档都由 `except` 捕获真实异常触发。所以故障注入不需要在里面加分支——
**在端口边界包一层装饰器，抛出与真实故障同形的异常即可**：

| 装饰对象 | 端口 | 注入后表现 |
|---|---|---|
| `EmbeddingClient` | `embed` / `embed_batch` | 向量路整条挂掉 → 降级到 `bm25_only` / `keyword_2gram` |
| `Reranker` | `rerank` | 精排挂掉 → `rerank_applied=false`，退回一阶段排序 |
| `QdrantProductIndex` | `search` | 向量库不可达 → 同 embedding 挂 |

好处是**生产代码路径一行不改**：不加 if、不加参数、不多一次判断。
风险也因此收敛到组装根一处——没开开关时装饰器根本不会被构造。

被否掉的方案：在 `catalog_search` 里读一个 `fault` 参数。
那等于把测试用的分支写进业务主路径，且每次读取都要判一次，
最终会变成"生产代码里躺着一条只有评测走的路"。

### 决策 2：双重开关——**编译期开关 + 运行时开关**

- `FAULT_INJECTION_ENABLED`（默认 `0`）：决定装饰器与 `/debug/faults` 端点
  **是否存在**。默认关时，生产进程里既没有装饰器也没有那个端点。
- 运行时 `POST /debug/faults {"components": [...]}`：在已启用的进程里选择当前注入哪些。

为什么要两层：评测是一个**长驻服务 + 逐条打 HTTP** 的形态，
31 条用例跑在同一个进程里，只有其中一两条需要故障。
做成纯环境变量的话，一条故障用例就要单独重启一次服务——
那等于这类用例永远不会被跑（同 `--tag smoke` 的道理：跑不动的判据等于没有判据）。

### 决策 3：注入状态必须**如实上报**到 `/health` 与报告配置行

这是踩坑 32 的同一条：**分数变了要能归因到配置**。
一个开着 reranker 故障的进程跑出来的报告，如果配置行不写这件事，
读报告的人只会看到"精排档的分数崩了"，然后去改检索参数。

所以 `/health` 增 `fault_injection` 字段（未启用时为 `false`，启用时列出当前注入的组件），
`run_identity` 的配置行原样渲染。

### 决策 4：注入不生效必须**报错**，不能静默跑过去

评测用例声明了 `faults: [reranker]`，而服务没开 `FAULT_INJECTION_ENABLED` 时，
这条用例会在"精排完全正常"的情况下跑完，然后**大概率 PASS**——
判据成了绿色装饰。这与 CI 里那条"没数据就当通过"是同一个陷阱。

所以 `eval_regression.py` 在应用故障失败时**直接把这条用例判为 ERROR**，
并在开跑前（服务体检那一步）就检查：有 case 声明了 faults 而服务未启用注入 → 拦下整轮。

### 决策 5：用例扩容优先补"判据能力"而不是"数量"

交接文档列的四个空白，按能挖出真问题的概率排：

| 空白 | 补法 | 优先级 |
|---|---|---|
| 工具失败注入 | 3 条（精排挂 / 向量库挂 / 检索全挂） | 高——现有 `tool-error-honesty` 只覆盖"目的国不支持"，真正的服务不可达没有用例 |
| `long-context-memory` 的 P1 加严 | 把"跨币种价格必须与事实表折算一致"提成 P0 | 高——八期出处校验在这条上抓到过 judge 放过去的真错 |
| 记忆类偏好冲突 | 1 条（先说不要塑料、后说要最便宜而最便宜的是塑料） | 中 |
| 更长的多轮链路 | 2 条（改主意 + 加购 + 改目的国叠加） | 中 |

目标 31 → **40 条**（+9）。验收标准沿用：**扩完之后整轮均分应当掉进 0.75~0.9**，
全过说明判据写松了。本期只入库，跑测留给有人值守时。

## 三、执行中的偏离

### 偏离 1：补了一组"降级链真的走到预期档位"的集成判据

原计划阶段 2 只做装饰器 + 单测。写完发现那些测试证明的只是**"装饰器会抛异常"**——
而 `catalog_search` 哪一档捕获它、捕获后 `recall_strategy` 标成什么，一条都没测。
若某个 `except` 恰好把它吞成了别的档位，故障用例照样跑完，判据却在验一个错的前提。

补法：真实 `CatalogSearchUseCase` + 真实 BM25 索引 + 被装饰的假 embedding/index/reranker，
逐档钉住 `recall_strategy` 与 `rerank_applied`，并加**一条不注入的对照组**
（没有对照，"注入后档位变了"也可能是别的原因）。教训进踩坑 36。

### 偏离 2：用例做到 40 条用了 9 条新用例 + 1 条加严

原计划表列的四类共 8 条，实际写到第 9 条（`de-minimis-cross-currency-quote`）才补齐
`$800` 的第三条路径——那正是十一期修的那个字段的行为侧验收，
不写这一条，"改了存储结构"这件事在评测里没有任何一条判据看得见。

### 偏离 3：顺带加了 `make serve-faults` 与 `.env.example` 条目

故障用例要求服务以 `FAULT_INJECTION_ENABLED=1` 启动。这件事只写在文档里迟早会被绕开
（十期教训：纪律写在文档里，判据没实现它）。所以：Makefile 给一个目标、
`.env.example` 给一段带 curl 示例的说明、评测脚本开跑前硬拦。
