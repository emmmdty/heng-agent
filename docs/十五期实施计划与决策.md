# 十五期实施计划与决策

仍由 Agent 自主规划执行；本文件是决策记录。

范围：**让跑测配置行说真话**——`/health` 与报告开头那行现在报的是"配置了什么"，
不是"实际生效了什么"。

## 一、缺口是怎么暴露的

十四期小样本实测（2026-09-04 01:52）的配置行写着：

    被测模型 mimo-v2.5｜评审模型 longcat-2.0｜提示词 c46a4a6a｜**精排 开**｜
    字面索引 开｜字面门限 4.0｜语义缓存 关｜代码 新鲜

而同一轮的落盘轨迹里，`recall_strategy` 是 **`bm25_only`**——
两条隧道（embedding 11436 / reranker 11437）当时都是 502，
**向量路整条不可用、精排一次都没跑过**。

配置行不是写错了，是它**问错了问题**：它读的是 `RERANKER_BASE_URL` 配没配，
而不是那个地址通不通。

后果与踩坑 32（服务跑着旧代码）完全同构：

- 一轮在精排不可用状态下跑出来的分数，报告上标着"精排 开"；
- 读报告的人拿它和"精排 开"的历史读数横向比较，结论必然是错的；
- 更糟的是可能得出"精排没用"——而真相是这一轮压根没有精排。

**这个项目所有方法论的落点都是"读数要能归因到配置"。配置行撒谎，
比没有配置行更坏。**

## 二、决策

### 决策 1：加深度探活 `GET /health?deep=1`，不改默认 `/health`

默认 `/health` 保持零外部调用：它同时是容器存活探针，
每 10 秒打一次外部服务既浪费又会把探针本身变得不稳定
（外部服务抖一下，容器被判死）。

深度探活只在**有人明确要读数**时发生：`eval_regression` 开跑前调一次，
`make health` 也走它。一次两个短超时请求，成本可以忽略。

### 决策 2：探活结果进 `retrieval.probe`，**不改既有字段的形状**

`retrieval.reranker`（配没配）保持 `bool` 不动——`run_identity` 与既有单测都读它。
新增 `retrieval.probe = {"embedding": "ok" | "error: ...", "reranker": ...}`，
只有深度探活时才出现。

**不把 `reranker` 直接改成三态**：那会让"没做深度探活"和"探活失败"
在渲染上混成一个样子，而这两件事的含义完全相反。

### 决策 3：配置行渲染成「配置 + 实测」两截

    精排 开(实测不可达)      配置开，探活失败 —— 这一轮没有精排
    精排 开                 配置开，探活成功或未探活
    精排 关                 没配

没探活时**不加任何后缀**：多一个"未知"标记只会让每一行都变长，
而真正要跳出来的是"配了但没生效"那一种。

### 决策 4：探活失败**不阻断**评测

只如实标注，不拦。理由：降级态本身就是要评的东西之一
（十二期专门为它写了 3 条故障注入用例）。拦下来等于宣称
"外部服务不全就不许评测"，那与"降级链要被检验"自相矛盾。

## 四、执行中的偏离

### 偏离 1：顺带修掉"报告与流水分家"

本期为了不抢用户实例的 Qdrant 文件锁，评测跑在 `DATA_DIR=临时目录` 的实例上。
结果 `make check` 红了：报告落在仓库 `eval/`、流水落在临时目录，
金额出处门禁两头对不上——**而报错指向"流水可能被清过"**，
把人引向完全错误的方向。

修法与本期主题是同一条（让读数自己说清它是哪来的）：
`/health` 报出 `data_dir` → 报告原样抄走 → 审计跟着报告走
（显式 `--dir` > 报告记的 DATA_DIR > 仓库默认），
并把那句报错改成按概率排的两条原因。
