范围：**回复里写出来的算式必须自洽**——把"过程写错、结果碰巧对"变成确定性判据。

基线：`696 单测`、用例 44 条；full3 实测 42/44 PASS、均分 0.976、
无出处金额率 4.9%（489 处金额）。

## 一、缺陷：算式里乘错了数，而结果是对的

`taxable-base-us-explained` 判 FAIL 0.517。Agent 的前三步完全正确：

    2. 确定计税基数：不是对全额征税！只对超出部分征——
       $886.34 − $800.00 = $86.34（这才是交关税的部分）
    3. 适用税率：7.5%
    4. 关税 = $886.34 × 7.5% = $6.48      ← 乘错了数

`886.34 × 7.5% = 66.48`，不是 6.48。**结果是对的（来自工具），过程是错的。**
它自己在第 2 步刚写对了基数，第 4 步又把小计抄了进去。

这与十期实测的 `1,199 × 12% ≈ ¥3.48` 是**同一个形状**，而中间隔着两次修：

| 期 | 修法 | 结果 |
|---|---|---|
| 十一 | 工具补 `taxable_base_major`，让模型有得可抄 | 它确实抄了——第 2 步写对了 |
| 十一 | 提示词写明"计税基数是超出免税额度的那部分，不是整单金额" | 仍然会滑 |

**两次都是"给它正确的东西"，而这次错的不是它拿到什么，是它写下来的那一行。**
按本仓一贯的判断：**提示词拦不住的，就该由确定性判据接管。**

## 二、决策

### 决策 1：判据只做一件事——**验算式自洽**

抽回复里 `A × B% = C` / `A − B = C` 形态的算式，验证等号两边是否相等。
不查出处（那是金额出处校验的事），不判对错口径（那是 judge 与 ground_truth 的事）。

**只验自洽的好处是它不需要知道业务规则**：`886.34 × 7.5% = 6.48` 不成立，
这件事与关税规则无关，纯算术就能判死。判据越薄，越不会误判。

### 决策 2：与金额出处校验并列，不合并

两者抓的是**互补的两类错**：

| 判据 | 抓什么 | 这次的例子 |
|---|---|---|
| 金额出处 | 数字**从哪来**——没有出处即可疑 | `$800` 凭知识说出来 |
| 算式自洽 | 数字**怎么来**——写出来的过程算不通 | `886.34 × 7.5% = 6.48` |

出处校验对这次的错完全无感：886.34、7.5%、6.48 三个数**都有工具出处**。
所以必须是两条独立判据。

### 决策 3：容差取"能容下展示取整，容不下量级错"

`86.34 × 7.5% = 6.4755`，回复写 `6.48` 是正常取整。
而 `886.34 × 7.5% = 66.48` 与 `6.48` 差一个数量级。
所以容差按**相对 2%**（能容下两位小数取整），不按绝对值——
金额量级跨度太大，绝对容差要么放过量级错，要么误伤大额取整。

### 决策 4：只告警，不改写回复

与金额出处校验同一条：轮末发现时本轮已经结束，注入纠正来不及；
价值在于**被看见**（进事件流与轨迹，供 bad case 回收）。
运行时发 `number.unsourced` 同类事件，离线扫描进审计脚本。

### 决策 5：范围刻意收窄

只认**显式写出来的算式**（含 `×`/`*` 与 `=`/`≈`），不做隐式推断。
理由同金额出处校验："宁可漏报不误报"——
自然语言里"大约是原价的两成"这类表述不做解析，解析它只会制造误报。
