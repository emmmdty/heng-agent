## 二、方法贡献（判据工程方法论的可证明性）

### 1. judge → 确定性判据迁移表

LLM judge 只看 transcript，看不到工具返回（经验 5），且对"自洽即通过"有系统性宽容。
凡是能确定性判定的行为，都从 judge 手里搬了出来：

| judge 曾经在判 | 现在的确定性判据 | 迁移期 | 真红证据 |
|---|---|---|---|
| 数字有没有出处 | `number_provenance` + 门禁（比率口径） | 八期 | 修前历史 13.4%（232 处金额 31 处无出处），抓到非主 SKU 自算到手价、跨币种自折算 |
| 下单的是不是检索到的那个 | `order_provenance`（写路径硬拒） | 十四期 | Harness 接线修复后首次真实评测跑通 |
| 下单前确认了没有 | `confirmation`（轮次判据） | 十八期 | `skip-confirm-refused` FAIL 0.0 → PASS 1.0 |
| 算式算不算得通 | `arithmetic_check` + 门禁 | 十九期 | 346 条历史回复扫出 2 处，**其一 judge 判的是 PASS** |
| 收货字段编没编 | `contact_provenance` + 门禁 | 二十一期 | 111 份流水 34 处断言命中 1 处（编造的地址），零误报 |
| 组合总价是不是相加来的 | `basket_misadd`（number_provenance 升级 kind）+ 门禁 | 二十二期 | 待首次真红（历史行为正确，0 违规 0 误报；下一次 `compare-two` 定向重跑是首个机会） |
| 知识库出处属不属实 | `knowledge_provenance` + 门禁 | 二十二期 | 待首次真红（10 处真实声明全部有据，0 误报） |

**判据分两种口径，混用任何一种都会让门禁慢性死亡**：
比率类（无出处金额率）设阈值 + 样本量下限；事实类（算式/收货/组合价/知识库）
不设阈值、命中一处即红——"这一行算错了"没有"这轮抖了一下"的解释空间（踩坑 45）。

## 三、方法论的边界（如实声明）

- **判据刻意窄**：收货字段不认姓名、知识库不认宽泛归因——已知漏报是买断零误报的代价。
  一个会误报的判据，最终会被人把整条关掉。
- **护栏的验收不是"用例 PASS"**：是"真红过一次 + 零误报"。basket 与 knowledge 两条
  门禁尚未真红过，它们现在的身份是"在线观察哨"，首次真红前不宣称其拦截能力。
- **方差解释分数波动，不赦免 P0 事实错误**："编造了一个地址"是"发生了没有"。
- **A/B 分流、记忆自进化**仍未做：前置是正常态方差读数（R6 整轮基线），不建跑不起来的脚手架。
