## 一、TDD 路径（每条判据的红绿记录，做完逐条回填）

每条判据的验证顺序固定：

```text
红：新单测跑出预期失败（贴失败输出）
绿：最小实现让测试通过
钉：轨迹保真 / 接线判据（防止"写完了没接上"，踩坑 37 的形状）
门：审计脚本进 make check，历史流水上验证（真红 / 零误报）
```

### R2 variance 分组键

- 根因：`config_key()` 把配置行**整行**当键，而行里含 `代码 新鲜(服务启动于 %m-%d %H:%M:%S)`
  ——重启即换组。同配置两轮在现有 60+ 份报告里从不相遇，方差工具建成后从未真正出过组。
- 修法：解析配置行的分段结构（`A｜B｜C`），**剔除易变段**（代码新鲜度的启动时刻），
  其余逐段保留（含评审模型——换尺子的轮次不该混在一起算，这是保守方向）。
- 红测试：两份 run_line 仅"服务启动于"不同 → 断言同组（现状会失败）；
  模型或提示词指纹不同 → 断言不同组。

### R3 basket_sum（组合总价错加）

- 缺陷事实（二十期实测）：模型把两个单品 `landed_price` 相加当组合总价
  （¥364 + ¥154 = ¥518，正确是 ¥492 = 小计 388 + 运费 104 + 关税 0，
  运费按**一次履约**计）。judge 判 PASS——每个加数都对，错的是模型推不出来的口径。
- 判据设计（方向：宁可漏报不误报）：
  - **违规判定需要三个条件同时成立**：金额无出处；成因分类是 ≥2 个 `landed_price` 值相加；
    会话内存在 `quote_basket` 报价且其组合总价与该金额不符。
  - 工具报过价而回复不采 → 违规（该信的不信）；工具没被调过 → 降级为 `suspected_sum` 线索
    （没有 ground truth 就不定罪）。
  - 相加结果恰好等于组合总价时金额本身有出处（工具数在出处池里），天然不触发。
- 真红证据来源：`data/conversations/eval-compare-two-*` 有 5 份会话同时含 518 与 492
  （开跑前已核实），审计扫历史应当命中并零误报。

### R4 knowledge_provenance（知识库出处）

- 缺陷事实（二十期分诊）：judge 结构上看不到工具返回，"知识库当时可不可用"它判不了；
  数值区间那半已由 judge 侧 ground truth 覆盖，**出处属实性这半是空的**。
- 判据设计：
  - 只认**显式出处声明**：回复里出现"知识库 / 品类洞察 / 选购指南"等指向 RAG 的表述；
  - 出处池：本会话 `category_insight_tool` 的**成功**返回（`insights` 非空）；
  - 工具报错 / 无调用 / 零命中而回复声称有 → `knowledge.unsourced`；
  - 排除诚实降级："知识库暂时不可用"类表述**不是**出处声明，模式里显式排除；
  - 反方向（工具返回了、回复没引用）不算错。
- 二十期的教训同步落地：判据只写 judge 判得了的事——出处属不属实看轨迹，归确定性判据。

### 决策 3：R3 的"真红 ≥1 次"验收在执行中被证伪，如实修订

开跑前核实历史流水时以为 518 就是缺陷现场，逐份读原文后发现：**4 处 518 全部
以"分开买合计 / 分别下单对照"出现——那是合法用法**（分开买各付各的运费，
加法恰好是对的），且 quote_basket 的 `separate_purchase_landed_major` 本身
就把 518 放进了出处池。最早那轮真正的缺陷（$51.26 + $21.69 被算成 $62.95）
不在流水库里。所以 basket_misadd 在 120 份历史流水上 **0 违规、0 误报**
——历史行为本来就正确。验收修订为：单测先红后绿 + 全库零误报 +
门禁落地；**真红等下一次 `compare-two` 定向重跑**（该用例正是探测这条路径的），
在其真红之前不宣称拦截能力（同"护栏必须真红过一次"的既定纪律）。

### 决策 4：knowledge_provenance 的模式必须用真实语料校准，不是拍脑袋

首版模式（出现"知识库 / 品类洞察"即声明）在 120 份流水上扫出 2 处，逐条分诊
**都是误报**：①"我可以提供品类洞察、热门款型、避坑指南"是**能力提议**，
没有把内容归因给知识库；②"说明知识库里这条数据不完整，我不能替它编一个数字"
是**缺失观察**——反过来罚它，下次它就会编。修法不是调阈值，是把语义钉进模式：
只认**归因构型**（来自/根据/知识库里/品类洞察显示…），另排除缺失与免责
（"暂无 / 不完整 / 非知识库数据"）。校准后 15 处声明行收敛为 10 处归因声明、
全部有据、零误报。**已知缺口（不补）**：无知识库返回的会话里编造
"知识库里没有 X"会漏过——宁可漏报不误报。
