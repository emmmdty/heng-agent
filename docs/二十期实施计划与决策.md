# 二十期实施计划与决策

范围：**让证据活过会话，让判据被人读到**。
两件都不是新做的能力，是十九期交接后复核读数时发现"读数与预期不符"挖出来的。

基线：`719 单测`、用例 44 条。
但本期开工时的第一件事就是：**十九期那批读数已经无法复算**（缺陷 1）。

---

## 一、缺陷 1：评测流水写进会话级临时目录，证据链跨会话必然断

现象：`make check` 第四项（金额出处）红，报错是
"报告里的 3 个会话在流水目录里一份都找不到"。

根因：09-04 的每一份报告，`health.data_dir` 都指向

    /tmp/claude-1000/<会话 id>/scratchpad/data

该目录随会话结束被清理。报告还留在仓库 `eval/` 里，指着一个已经不存在的路径。

**为什么会这么配**：交接文档地雷 11 原本建议"要在不打扰已有服务的前提下起第二个实例，
用 `DATA_DIR=<临时目录>` 换一份 Qdrant 存储"——Qdrant 本地嵌入模式是单进程文件锁，
不换个地方就起不来第二个实例。这条建议解决的是当轮的问题，代价写在下一个会话里。
**文档里的绕坑建议本身就是这次的陷阱来源。**

血本：十九期整批读数——无出处金额率 4.9%、346 条回复的算式扫描、bad case 采集——
事后一条都无法复算。**报告活着，它引用的证据死了**，而当轮没有任何症状：
`make check` 当场是绿的。

要害在于：**同一个开关同时管着"可重建的缓存"和"不可再生的证据"**。
Qdrant 落盘删了可以重建，流水删了就没了，而两者共用 `DATA_DIR`。

## 二、缺陷 2：十九期的算式自洽校验只做了"检测"，没做"暴露"

现象：`arith.inconsistent` 事件在 app 之外**零消费方**——不进 `make check`、
不进报告、没有审计脚本。grep 全仓只有 app 自己和它的单测。

对照：`number.unsourced` 有 `audit_number_provenance.py` + `make check` 门禁，是闭环的。
两条判据同期同形状，一条闭环、一条只发事件。

十九期计划的阶段 3 白纸黑字写的是"编排器轮末检查 + 事件 + **离线审计脚本**"，
第三项从未落地。那份"346 条回复、抽出 4 个算式、命中 2 处、零误报"的读数
是一次性手工扫描，结果被硬编码成 `tests/test_arithmetic_check.py` 里的两个字符串，
**没有可重跑的脚本**。

净效果：判据写进流水，而流水正好被缺陷 1 删掉了——
**这道判据在真实评测里等价于不存在**。

---

## 三、决策

### 决策 1：把"可重建的缓存"与"不可再生的证据"拆成两个开关

新增 `VECTOR_STORE_DIR`（空 = 跟随 `DATA_DIR`，单实例默认行为一字不变）。
Qdrant 的两个消费方改吃 `settings.vector_store_dir`：

| 消费方 | 落盘子目录 |
|---|---|
| `app/infrastructure/vector/qdrant_product_index.py` | `qdrant/` |
| `app/infrastructure/rag/category_knowledge.py` | `qdrant_kb/` |

`DATA_DIR` 从此只管流水 / 会话 / 偏好。想躲文件锁就挪向量库，不要挪证据。

### 决策 2：开跑前拦截，而不是事后解释

`eval_regression.py` 开跑前读 `/health` 报的 `data_dir`，落在系统临时目录下就拒跑，
错误信息里直接给出正确写法（`VECTOR_STORE_DIR=... uvicorn ...`），
逃生阀是 `--allow-ephemeral-data-dir`。

理由与 `code.stale` 那道拦截同源：**这类错误的唯一症状出现在几十分钟之后，
而且指向完全错误的方向**（报错说的是"流水可能被清过"，不是"你把 DATA_DIR 指错了"）。
拿不到 `data_dir` 的老服务不拦——不把老服务锁死。

### 决策 3：验证方式必须是"真起两个实例"，不是断言配置字段相等

断言 `settings.vector_store_dir == X` 只证明读对了值，证明不了 Qdrant 换了地方开锁。
所以验收判据定成：**8000 占着 `data/qdrant` 锁的同时，
`VECTOR_STORE_DIR=<临时目录>` 起的第二个实例能正常启动**。

（这是踩坑 42「我按'用例过了'验证护栏，而护栏根本没接上」的同一条纪律：
护栏的验收判据得是它真做到了那件事，不是它的配置看起来对。）

### 决策 4：审计脚本形状照抄出处审计

新增 `scripts/eval/audit_arithmetic.py`，与 `audit_number_provenance.py` 同形：
`--report latest` 把范围收敛到本轮（累积目录不能扫全量，同经验 7）、
一份会话都匹配不上就报错退出（0 个算式算出的"0 处问题"会被门禁当满分放行，
比红灯更危险，同踩坑 33）。进 `make check` 成为第五项。

`scripts/eval/trace_audit.py` 增 `ARITHMETIC_WARNING_EVENT` 与 `SessionTrace.arith_warnings`，
用来区分**"运行时已告警"与"本次补判发现"**——后者说明那份流水跑在判据落地之前，
它是"改动之前"的对照数据。

### 决策 5：门禁口径与出处审计**故意不同**——不设阈值、不设样本量下限，命中一处即红

| 判据 | 口径 | 为什么 |
|---|---|---|
| 金额出处 | `--max-ratio` + `--min-sessions` | 是**比率**指标：对已有出处数字的修辞取整本来就占几个点，小样本上不判定是对的 |
| 算式自洽 | 无阈值、无下限，1 处即红 | 是**事实错误**：`886.34 × 7.5% = 6.48` 能指着原文说"这一行算错了" |

"发生了没有"不是"高了低了"，没有摊薄它的口径。
这是踩坑 45「方差不能用来赦免 P0 事实错误」的同一面：
比率指标容得下噪声，具体的事实错误容不下。

一处刻意保留的诚实：**"本轮 0 处问题"要分清是"判过了、全对"还是"压根没东西可判"**。
判据只认显式写出的百分比乘法（346 条回复里只抽出 4 个），
所以未抽出算式时门禁明说"判据无从判定"，不冒充满分。

## 五、执行中的偏离

### 偏离 1：给临时目录拦截写测试时，对照组选错了

第一版用 pytest 的 `tmp_path` 当"正常路径"的对照组，断言它不该被拦——**测试红了**。
原因很朴素：`tmp_path` 自己就在 `/tmp` 下，护栏拦得完全正确，是测试写错了。
改成拿 `PROJECT_ROOT / "data"` 当对照组。

值得记一笔的一般化：
**给"路径必须在某处之外"写测试时，测试框架给的临时目录不能当对照组**——
它恰好就在你要排除的那个"某处"里面。

## 六、执行结果

- **742 单测绿**（十九期是 719，新增 23 条，全部先红后绿）
- `make check` **五项全绿**（单测 + 标注集 + 用例自检 + 金额出处 + **算式自洽**）

### 缺陷 1 的验收证据：两个实例真的同时活着

8000 端口的服务占着 `data/qdrant` 的文件锁不动，
`VECTOR_STORE_DIR=<临时目录>` 起的 8011 正常启动；
且 8011 的 `/health` 报的 `data_dir` 仍是仓库 `data/`——
**换掉的只有向量库，流水没跟着走**。

### 缺陷 2 的验收证据：护栏必须真红过一次

拿 50 份历史流水实跑 `audit_arithmetic.py --gate`，**退出码 1**，
抓到的正是十九期手工找到的那两处：

    [eval-de-minimis-boundary-eu] 1,199 × 12% ≈ ¥3.48   → 应为 143.88
    [eval-de-minimis-far-above]   €384.49 × 12% = €28.14 → 应为 46.14

区别在于：**现在它们是可重跑的读数，不再是测试里的两个硬编码字符串。**
一道只会绿的门禁没有信息量——它得先红一次，才算证明自己接上了（踩坑 42、经验 3 同一条）。
